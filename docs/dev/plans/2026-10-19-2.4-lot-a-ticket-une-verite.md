# F2.4 lot A — Un ticket, une seule vérité : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Une fiche par ticket qui dit la vérité : champs avec origine, édition à la main partout, prochaine étape calculée depuis les todos, notes liées par métadonnée, demandes à l'agent, complétude, et un accueil qui lit la même fiche.

**Architecture:** Tout reste dans le module dev (`src/work/`) et l'état SQLite (une migration de plus). Chaque geste est une opération du moteur (`defineOperation`) utilisée par le web, la CLI et `okb mcp`. Le cœur (`src/projects/`) ne connaît pas les tickets : l'accueil reçoit les cartes de ticket par le contrat `ProjectSource` (F2.0-25).

**Tech Stack:** TypeScript, Node 22.13+, `node:sqlite`, zod, vitest, React (web-app), Playwright pour les parcours.

**Spec:** `docs/dev/specs/2026-10-19-2.4-ticket-une-verite.md` (maquettes de référence hors dépôt, validées le 19 octobre 2026).

## Global Constraints

- Node 22.13+ ; aucune nouvelle dépendance.
- Markdown pour le savoir, SQLite pour l'état ; aucune écriture dans une KB hors proposition.
- OKB ne contacte ni Jira, ni ServiceNow, ni un wiki ; seul l'agent lit ces sources ; OKB n'y écrit jamais.
- Une migration SQLite ajoutée en fin de `MIGRATIONS` (`src/state/db.ts`) ; on ne modifie jamais une migration livrée.
- Valeur refusée (champ reste non défini) : vide, `inconnu`, `unknown`, `TBD`, `à définir` (sans casse, espaces rognés), ou égale à la référence du ticket.
- Origines : `person`, `agent`, `jira`, `servicenow`, `wiki`, `github`, `other`. Liens : `safeUrl` existant.
- Limites : `title` 200, `summary` 600, `description` 8 000, `sourceStatus` 80, `team` 120, `product` 120, `done` 1 000, `blocker` 600 caractères.
- Importance : `low` | `medium` (défaut) | `high` ; une seule todo épinglée par ticket.
- Complétude : 10 rubriques de même poids, arrondi entier, 0 rubrique applicable → 0 %.
- « Compris » fait à partir de 70 % ; « débloqué récemment » = passé de `waiting`/`blocked` à `none` depuis moins de 3 jours.
- `assertNoSecrets` sur toute valeur écrite.
- Thème Atelier, français et anglais (i18n existante), mode sombre ; chaque couleur double un mot ; actions au survol atteignables au clavier ; cibles ≥ 28 px.
- Le dépôt est public : données fictives seulement ; scan `.dev/private-leaks.txt` avant toute demande de push.
- Ni commit, ni push, ni tag sans demande explicite du mainteneur ; jamais de co-auteur. Les étapes « Point de contrôle » remplacent les commits.
- Citer F2.4-08 à F2.4-14 et D70 dans le code commenté, les tests (`describe`) et les docs.

## Review Focus

1. **Deux appels simultanés** (web et agent) sur le même champ : le dernier gagne sans perdre le repère `manual`, et un écart n'est jamais créé deux fois → test dans la tâche 2.
2. **Ticket déjà migré une fois puis rouvert par une 2.0.0** (retour arrière) : les anciennes colonnes restent lisibles et rien n'est supprimé → test dans la tâche 5.
3. **Note supprimée ou déplacée après liaison** : la liaison confirmée pointe vers un chemin absent ; la fiche l'affiche comme « note introuvable » au lieu de planter, et le scan la relie par son `id` OKF si elle a bougé → test dans la tâche 7.
4. **Référence en casse différente** (`demo-4211`, `DEMO_4211`) dans `tickets:` ou dans une todo `#demo-4211` : normalisée par `ticketId` → tests dans les tâches 3 et 7.
5. **Module dev désactivé** : l'accueil n'affiche ni cartes de ticket ni demandes, et les todos rattachées à un ticket restent visibles comme personnelles sans planter → test dans la tâche 10.
