La même interface React, le même serveur loopback et le même moteur Node sont emballés dans Electron. Pas de seconde application ni de nouveau service cloud. Le port est attribué automatiquement ; l’application ne prend pas le port d’un serveur déjà lancé.

## Sécurité et cycle de vie

Renderer sandboxé, isolation du contexte, intégration Node désactivée, permissions refusées par défaut, navigation limitée à l’origine locale exacte, fenêtres et webviews interdites. La CSP du serveur reste en place. Un preload CommonJS expose seulement le choix de dossier et quatre gestes de mise à jour ; aucune commande, aucun accès arbitraire aux fichiers ou à IPC.

Un build de développement n’active pas les mises à jour. Un build signé doit fournir deux feeds HTTPS et le nom du signataire ; aucun feed, certificat ou compte payant n’est créé automatiquement. Le build peut être produit localement sans signature pour les essais, ce qui ne vaut pas une application distribuable au grand public.

Build et runtime choisissent ensemble le canal stable (`latest`) ou préversion (`beta`), quelle que soit la forme du suffixe alpha/rc/preview. Le feed de sortie correspond au canal. Sur Mac, codesign contrôle le bundle installé ; sur Windows, Authenticode contrôle l'exécutable et son éditeur, en plus des métadonnées de mise à jour. Les tests unitaires vérifient la politique ; la signature réelle et les mises à jour sur les deux OS restent à essayer.

L’application garde Markdown lisible et SQLite local. L’export copie le format de sauvegarde entier (`kb`, `state`, `profile`, manifeste), sans clé d’approbation, et refuse un dossier non vide ou imbriqué avec le cerveau ou son état. Sauvegarde, vérification, export et restauration partagent un verrou par profil ; le snapshot précédent reste récupérable pendant la publication. Les sauvegardes automatiques suivent aussi la création d'un espace après le démarrage et le changement d'espace actif. Une seule instance desktop est ouverte ; la fermeture arrête les entrées et ses agents contrôlés, attend les écritures et sauvegardes engagées, puis ferme les connexions SQLite. Le serveur CLI utilise le même drain.

## Commandes et essais

Une erreur de parcours ou de lecture d'un fichier recensé arrête la sauvegarde et conserve l'ancien snapshot. L'état d'un espace neuf et un fichier de profil absent peuvent être absents ; une erreur de permission ou d'entrée/sortie ne vaut jamais absence. Les anciens dossiers `.partial` et les temporaires de création interrompus sont récupérés sous verrou, sans supprimer les noms étrangers.

`npm run desktop:dev`, `npm run desktop:dir`, `npm run desktop:build`. `desktop:release` exige le mode signé et les contrôles, dont les parcours navigateur ; `--publish never` est systématique. Aucun upload implicite. Les variables de distribution sont documentées dans le guide desktop.

Références consultées : [sécurité Electron](https://www.electronjs.org/docs/latest/tutorial/security), [signature](https://www.electronjs.org/docs/latest/tutorial/code-signing), [mise à jour](https://www.electronjs.org/docs/latest/tutorial/updates).

La porte des proches (installation seuls, résultat en dix minutes, deux semaines d’usage) et les essais des artefacts signés restent externes. Un build local Mac non signé ne passe aucune de ces portes à lui seul.
