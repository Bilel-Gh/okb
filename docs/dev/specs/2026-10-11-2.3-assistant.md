## Architecture et limites

Les conversations sont dans SQLite, hors des notes, hors du partage. Le même moteur sert les routes de l’application. Les opérations de conversation sont réservées à la personne. Le MCP des sessions intégrées ne propose que les outils de lecture sélectionnés ; approbation, application, shell et édition ne sont pas exposés par OKB. Les processus n’utilisent pas de shell et ont des limites de temps, de taille et une annulation.

La porte IA commune contrôle tout le message et le budget avant l’appel, puis compte l’usage même quand la réponse ne convient pas. Un usage CLI non rapporté est affiché inconnu ; le budget réserve alors une estimation explicitement identifiée. Les notes/documents verrouillés sont exclus. Les sources sont un instantané borné ; les anciennes réponses ne sont pas réinjectées avec d’anciens contenus devenus privés.

Une citation présente est une preuve de ce que le texte contient, **pas un contrôle automatique de véracité ni d’implication sémantique**. Les notes peuvent être anciennes ou erronées. L’interface permet de revenir à la source ; l’agent doit signaler l’incertitude et le manque d’information.

Le processus CLI conserve les réglages de l’agent dans un dossier de travail vide dédié à OKB. Les réglages personnels restent une frontière de confiance : les hooks/configurations autorisés par la personne ne deviennent pas un sandbox OS du simple fait de l’intégration. Aucune nouvelle connexion OAuth ni extraction de jeton.

Sources techniques consultées le 11 octobre 2026 : [Claude CLI programmatique](https://code.claude.com/docs/en/headless), [référence Claude](https://code.claude.com/docs/en/cli-reference), [Codex non interactif](https://learn.chatgpt.com/docs/non-interactive-mode), [configuration Codex](https://learn.chatgpt.com/docs/config-file/config-reference). Elles établissent les interfaces documentées ; elles ne remplacent pas une vérification contractuelle pour une distribution tierce.

## Essais de CLI sur données fictives

Le 11 octobre 2026, Codex CLI `0.159.0-alpha.12.1` a réellement appelé
`notes_find` et `notes_read` par MCP OKB, puis rendu le chemin, le titre et
une citation exacte de la fixture Dispatcher. Le test conserve les réglages
d’authentification ; la carte MCP est remplacée pour cette invocation par
le seul serveur OKB, avec shell, web, apps et sous-agents désactivés.
Il ne certifie pas d’autres versions, ni le parcours complet d’une conversation.
`OKB_ASSISTANT_EXPERIMENTAL_CODEX=1` permet le test de cette version ; le
statut de connexion demeure non vérifié avant la première demande réussie.

L’appel mesuré rapporte 56 268 tokens d’entrée (dont 40 448 en cache) et
163 de sortie. Ce volume comprend le contexte propre de la CLI et ses outils,
pas seulement la question OKB. Le budget avant appel repose sur une estimation
du message contrôlé ; il ne garantit pas un plafond strict de consommation
du fournisseur. L’usage rapporté corrige le compteur après l’appel. Cette
surcharge reste à mesurer avec les configurations de pilotes avant de
présenter l’intégration comme optimisée en coût.

Claude Code `2.1.289` a été détecté. L’essai sur la même fixture a échoué ;
la cause n'a pas été établie. Le succès de génération réel reste
à valider. Les tests simulés vérifient le protocole, la compatibilité minimale,
l’annulation, les sources et les refus, pas le compte ni son quota.
