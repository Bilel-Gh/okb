# Partager avec un collègue

Dans **Mémoire → Partager**, choisis la copie locale du dépôt commun autorisé et le nom de ton tiroir. Confirme que cet emplacement est permis pour tes notes de travail. Ton cerveau personnel reste dans son propre dossier.

1. Marque une note ou un dossier de projet à partager.
2. Ouvre l’aperçu : il montre le texte exact, ce qui reste privé et les copies à retirer.
3. Confirme que tu as relu. **Préparer localement** actualise ton tiroir ; **Envoyer** fait aussi le commit et le push explicitement demandés.
4. **Recevoir** récupère les changements du dépôt commun. Les notes de ton collègue deviennent recherchables avec son nom.
5. **Garder dans mon cerveau** prépare un changement à relire et approuver, comme toute rédaction proposée.

Si tu changes une note après l’aperçu, ouvre un nouvel aperçu. Les fichiers hors sélection, même déjà indexés, restent locaux. Des commits antérieurs non publiés bloquent l'envoi et doivent être vérifiés avec Git. Une divergence ou un conflit demande aussi une intervention explicite. Un envoi échoué peut laisser le commit dans ta copie locale : sa publication doit alors être faite manuellement après contrôle.

La carte compare les sujets des notes disponibles ; elle ne mesure pas la compétence d’une personne. Le glossaire retrouve les concepts de chacun. L’onglet **Packs** conserve les échanges ponctuels de la 1.5.

Tes notes verrouillées, privées, ton bagage et ta carrière ne partent pas. Retirer une copie déjà envoyée ne la supprime pas de l’historique du dépôt ni des machines des autres. Les droits d’accès au dépôt se règlent dans GitHub ; le nom d’un tiroir n’est pas un contrôle d’accès.
